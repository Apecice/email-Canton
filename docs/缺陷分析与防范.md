# 缺陷分析、根因与今后如何避免

本轮用 TDD（先写失败用例 → 修复 → 跑绿）补齐了错误场景覆盖。下面逐条说明
**发现的缺陷、根本原因、修复方式，以及今后如何从源头避免**。

测试位于 `tests/`，全部用 Python 标准库 `unittest`，**不联网、不需要真实邮箱**
（用伪造的 IMAP 客户端驱动）。运行：

```
python -m unittest discover -s tests -p "test_*.py" -v
```
或在 Windows 上双击 `run_tests.bat`。共 42 个用例。

---

## 安全性结论（先回答"会不会泄露数据"）

**不会。** 并且现在有自动化测试持续守护这一点：

- `test_privacy.py::TestNeverFetchesBody` —— 断言我们**只**用
  `BODY.PEEK[HEADER.FIELDS (...)]` 取头字段，**绝不**请求 `BODY[]`、`BODY[TEXT]`、
  `RFC822.TEXT`。`PEEK` 还保证不会把邮件标记成"已读"。正文一个字节都不下载。
- `test_privacy.py::TestNeverLeaksSecrets` —— 实际跑一轮采集后，扫描落盘的所有日志，
  断言**密码字符串从不出现**，且默认模式下**发件人/主题以哈希形式存储、原文不出现**。
- `test_privacy.py::TestRedaction` —— 哈希可复现、随盐值变化、不可逆、空值安全；
  且**配置项拼错时回退为哈希**（fail-safe），绝不会因笔误而泄露原文。

## 缺陷清单

### 1. 密码/账号错误 → 无限重连，且永不告知用户
- **现象**：登录被服务器拒绝（密码错）时，旧代码把它当成普通"断线"，每隔 backoff
  秒重连一次，**无限循环**，用户永远看不到"密码错了"的提示。
- **根因**：错误处理**没有区分"永久性错误"和"暂时性错误"**——把协议级拒绝
  （`IMAP4.error`）和网络抖动（`OSError`）一视同仁地重试。
- **修复**：新增 `_is_permanent_error()` 与 `PermanentError`。
  - `imaplib.IMAP4.abort`（连接被断开，需要重连）→ **暂时性**；
  - `imapclient.LoginError` / `imaplib.IMAP4.error`（协议级拒绝：密码错、邮箱不存在）
    → **永久性**，记录 `auth_error` 事件并**立即停止**，不再空转。
- **覆盖用例**：`test_errors.py::TestAuthFailureStopsInsteadOfLooping`、
  `TestPermanentErrorClassification`。
- **今后避免**：凡是有"重试"逻辑的地方，**必须先对异常分类**（可重试 / 不可重试），
  并为不可重试错误留一条清晰的、对用户可见的退出路径。

### 2. 收件箱文件夹名写错 → 同样无限重连
- **根因**：同上，`select` 失败也被当成暂时性错误。
- **修复**：`_establish_*()` 把 `select` 的协议级失败包装为
  `PermanentError(kind="mailbox")`，记录 `mailbox_error` 并停止。
- **覆盖用例**：`test_errors.py::TestBadFolderStops`。

### 3. 配置缺失/格式错误 → 抛出难懂的堆栈
- **现象**：少写一项配置或 ini 语法错，程序直接崩出 Python traceback，非技术用户无从下手。
- **根因**：**缺少输入校验**，直接读取配置项；`load_config` 用 `sys.exit` 不利于测试。
- **修复**：新增 `common.ConfigError` 与 `common.validate_config()`，**一次性列出所有
  缺失/为空的必填项**；`load_config` 捕获解析错误并抛 `ConfigError`；`main()` 统一
  捕获后打印友好中文/英文提示并以退出码 2 退出。
- **覆盖用例**：`test_errors.py::TestConfigValidation`（缺文件/格式错/缺项/空值/正常）。
- **今后避免**：所有外部输入（配置、命令行、网络响应）**进入主流程前先校验**，
  失败要给"人话"提示而非堆栈。

### 4. IDLE 模式下 Ctrl+C 最长要等 5 分钟才响应
- **现象**：`idle_check(timeout=300)` 一次阻塞整段；而我们自定义的信号处理只是置位
  `_STOP` 标志、并不抛 `KeyboardInterrupt`，于是停止请求要等当前这段 IDLE 跑完才生效。
- **根因**：**长阻塞调用没有切片**，停止标志无法被及时检查。
- **修复**：新增 `_idle_wait()`，把等待切成 ≤15 秒一片
  （`IDLE_SLICE_SECONDS`），每片之间检查 `_STOP`，因此最多 ~15 秒即可响应停止。
- **覆盖用例**：`test_errors.py::TestGracefulStop`。
- **今后避免**：任何可能长时间阻塞的等待都应**切片轮询停止标志**，或使用可被唤醒的原语。

### 5. 网络探测把"TLS 证书错误"误报成"连不上"
- **现象**：TCP 其实连通了，只是 TLS 握手/证书校验失败，旧代码 `ok=False`，
  汇总时被统计成"连接失败"，**污染了"跨境是否连得通"这个关键证据**。
- **根因**：用单一布尔 `ok` 同时表示"TCP 连通"和"TLS 成功"两件不同的事。
- **修复**：`net_probe` 增加 `tcp_ok` 字段——TCP 一旦连上就为真；`report` 区分
  `tcp_fail`（真正的连通性失败）与 `tls_fail`（连得上但证书/握手有问题）。
- **覆盖用例**：`test_netprobe.py::test_tls_failure_against_plain_socket_still_marks_tcp_ok`、
  `test_report.py::test_netprobe_counts_tcp_failures`。
- **今后避免**：**一个变量只表达一件事**；诊断类指标尤其要把不同失败层次分开记录，
  否则证据会自相矛盾。

### 6. 代码无法测试（直连真实服务器）
- **根因**：`run_idle`/`run_poll` 内部直接 `new IMAPClient(...)`，无法在不联网的情况下测试。
- **修复**：引入**依赖注入**——`connect` / `make_client` 工厂参数，外加 `max_cycles`
  / `max_reconnects` 边界，使核心逻辑可用伪造客户端驱动；并把内联逻辑拆成可单测的小函数
  （`_establish_*`、`_idle_wait`、`_check_alive`、`_handle_new_idle`）。
- **今后避免**：**外部依赖（网络/IO）通过参数注入**，业务逻辑与 IO 分离，天然可测。

### 7. INTERNALDATE 跨时区解析（回归保护）
- **说明**：你的电脑是 UTC+8，邮件时间若按本机时区解析会算错"延迟"。经测试现有实现
  借助 `Internaldate2tuple` + `mktime` 已能正确归一到 UTC；新增用例在
  `TZ=Asia/Shanghai` 下固定这一行为，**防止今后改动引入时区回归**。
- **覆盖用例**：`test_parsing.py::TestInternaldate`（含 +0000 / +0800 / 非 UTC 本机时区）。

### 8. IMAP `N:*` 区间查询的"回声"陷阱（回归保护）
- **说明**：IMAP 中 `UID N:*` 即使没有新邮件也会返回当前最高 UID。若不过滤会**重复
  上报已见过的邮件**。现有实现已用 `u > seen_max_uid` 过滤，新增用例固定该行为。
- **覆盖用例**：`test_parsing.py::test_handle_new_idle_filters_uid_quirk`。

## 今后避免同类问题的几条总则

1. **异常先分类，再决定重试还是停止**；不可重试错误必须对用户可见。
2. **所有外部输入先校验**，失败给"人话"提示，不要抛裸堆栈。
3. **长阻塞调用要切片**，定期检查停止标志，保证可中断。
4. **一个变量/字段只表达一件事**，诊断指标按失败层次分开记录。
5. **IO 与逻辑分离 + 依赖注入**，让核心逻辑可在离线、无真实账号下测试。
6. **新增/修改行为时同步加测试**（尤其是隐私不变量、时区、协议怪癖这类容易回归的点）。
